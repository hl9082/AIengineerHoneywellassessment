# Search Query Quality Rating with Neural Networks

## Overview

This project builds and evaluates neural-network regression models that predict the quality of a user's search query.

Each query receives a numerical rating from **0 to 1**:

- Ratings near **0** represent vague, unclear, incomplete, or meaningless queries.
- Ratings near **1** represent clear, specific, and meaningful queries.

The project demonstrates an end-to-end workflow that includes data validation, conservative text cleaning, exploratory analysis, baseline comparison, neural-network experimentation, overfitting controls, Mean Absolute Error evaluation, whole-model serialization, restoration testing, and submission generation.

## Important note about the data

The included datasets are synthetic mock data created for development and educational testing. The current mock files contain 5,000 training observations and 1,000 test observations.

The ratings were generated by programmed mock-quality rules with controlled random variation. They are not human-validated measurements of real users' query quality. Validation results therefore measure how well the models learn the synthetic labeling patterns, not how reliably they judge real-world users.

## Problem statement

The goal is to predict a continuous query-quality rating from 0 to 1. This is a regression problem because the model predicts a numerical value rather than a category.

The required evaluation metric is **Mean Absolute Error**, or MAE. MAE is the average absolute distance between actual and predicted ratings. Lower values are better, and zero represents perfect predictions.

## Why preprocessing is separate from the serialized model

The mock dataset intentionally contains multilingual Unicode text. An earlier design placed a learned `TextVectorization` layer inside the saved Keras model. On the Windows environment used for this project, Keras attempted to serialize the vocabulary through the legacy `cp1252` encoding and raised a `UnicodeEncodeError`.

The revised design separates text preprocessing from the serializable numerical model:

```text
Raw query text
    ↓
TextVectorization
    ↓
Integer token sequence
    ↓
Serialized Keras neural network
    ↓
Predicted rating
```

This design preserves multilingual queries while still using whole-model serialization for the trained neural network.

## Whole-model serialization strategy

The project uses Keras `.keras` whole-model serialization for candidate checkpoints and the final neural network.

The complete numerical neural model contains:

- Model architecture
- Layer configuration
- Learned weights
- Compilation information
- Optimizer state

The model expects fixed-length integer token sequences rather than raw strings.

The raw-text preprocessing information is stored separately as UTF-8 JSON:

- `text_vectorizer_config.json` stores vectorizer settings.
- `text_vectorizer_vocabulary.json` stores the ordered vocabulary.

Together, these files reconstruct the complete query-to-rating prediction pipeline.

## Modeling workflow

### 1. Import libraries and configure paths

The notebook imports Python, Pandas, NumPy, Matplotlib, scikit-learn, TensorFlow, and Keras tools. A fixed seed is applied to improve repeatability.

### 2. Load and validate input files

The notebook loads:

```python
data = pd.read_csv(TRAIN_PATH, encoding="utf-8")
test_data = pd.read_csv(TEST_PATH, encoding="utf-8")
```

It requires `train.csv` to contain exactly `query` and `rating`, and `test.csv` to contain exactly `query`.

### 3. Clean query text

Cleaning replaces missing queries with empty strings, converts other values to text, collapses repeated whitespace, and trims surrounding whitespace. It preserves meaningful punctuation, numbers, and multilingual characters.

### 4. Explore the data

The notebook summarizes ratings, word counts, character counts, and the relationship between query length and rating. It uses the 95th-percentile query length, bounded between 10 and 100 tokens, as the neural input length.

### 5. Create training and validation groups

Eighty percent of usable labeled rows train the models. Twenty percent form a validation group used for model selection. The final test queries are not used for model selection.

### 6. Establish baselines

The notebook evaluates:

- A constant mean-prediction baseline
- A character TF-IDF plus Ridge regression baseline

These references show whether the neural networks improve on simpler methods.

### 7. Learn and apply text vectorization

A Keras `TextVectorization` layer learns vocabulary from the training partition only during evaluation. Queries are converted into fixed-length integer token sequences before being passed to the neural networks.

### 8. Compare two neural networks

#### `AveragePoolingNN`

This architecture uses token embeddings, global average pooling, dense layers, dropout, and a sigmoid output.

#### `BidirectionalGRUNN`

This architecture uses token embeddings, a bidirectional GRU, a dense layer, dropout, and a sigmoid output. The GRU can model token order in both directions.

### 9. Control overfitting

The notebook uses:

- Validation monitoring
- Dropout
- L2 regularization
- Early stopping with restored best weights
- Learning-rate reduction
- Best-only whole-model checkpoints

### 10. Select and diagnose the best model

The candidate with the lowest validation MAE is selected. Diagnostic charts show actual versus predicted ratings, residual distribution, and residuals versus predictions.

### 11. Refit on all labeled data

After model selection, a final vocabulary and final integer sequences are built from all usable labeled data. The selected architecture is retrained for the best epoch count found during validation.

### 12. Save and restore artifacts

The final model is saved as:

```text
outputs/best_query_rating_model.keras
```

The notebook then reloads the vectorizer artifacts and `.keras` model, reproduces sample predictions, and asserts that restored predictions match the original predictions within a small numerical tolerance.

## Loading the saved prediction pipeline

The final notebook module demonstrates the complete restoration process. In summary:

1. Read `text_vectorizer_config.json` as UTF-8.
2. Read `text_vectorizer_vocabulary.json` as UTF-8.
3. Rebuild `TextVectorization` with the saved settings and vocabulary.
4. Load `best_query_rating_model.keras` with `keras.models.load_model()`.
5. Vectorize raw query text.
6. Pass the integer sequences to the loaded model.

The saved neural model does not accept raw strings directly. This separation is intentional and avoids the Unicode serialization problem while retaining whole-model serialization for the learned neural network.

## Evaluation metric

Mean Absolute Error is calculated conceptually as:

```text
MAE = average(|actual rating - predicted rating|)
```

Lower MAE is better. Because the ratings are synthetic, the score should be interpreted as performance against the programmed mock-labeling process.

## Limitations

- The labels are synthetic rather than human-reviewed.
- Query quality is context-dependent.
- The model receives no user, location, session, or conversation context.
- Multilingual coverage may be uneven.
- Synthetic traffic may not represent real search behavior.
- Strong synthetic validation performance does not guarantee real-world accuracy.

## Ethical and privacy considerations

A low score should not automatically deny service or suppress a user's request. Short or unusual queries may come from mobile users, non-native speakers, people using accessibility tools, people with limited literacy, or users whose intent is already known from context.

Real search queries can contain names, addresses, health concerns, financial information, account information, or other personal data. Real-world deployments require privacy review, secure handling, retention controls, fairness testing, multilingual evaluation, and appropriate human or fallback mechanisms.
